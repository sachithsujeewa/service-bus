# Agentic Knowledge Vault — Judge Demo Outline

Audience: judge panel | Duration: ~10 minutes | Language: English
Style target: Hand-drawn technical explainer (手绘技术解释风)
Thesis: A knowledge base alone is a book. Skills + micro-workflows + typed knowledge create a matured architect that can execute long-horizon work without re-explaining context every time.

## Slide 1: Agentic Knowledge Vault
- Role: cover
- Key points:
  - Title: Agentic Knowledge Vault
  - Subtitle: From vibe coding to durable execution
  - Context: judge evaluation of the `base/` framework
- Visual idea: Simple vault + small agent/architect sketch; calm cover with lots of whitespace

## Slide 2: Why we triggered this
- Role: problem / context
- Key points:
  - Everyone is using vibe coding
  - We were in good shape with vibe coding — until scale hit
  - The trigger: every task needed fresh contextual understanding as input
- Visual idea: Smooth vibe-coding path that starts cracking; “good shape → why?”

## Slide 3: The hidden tax of vibe coding
- Role: problem breakdown
- Key points:
  - NO contextual understanding that persists
  - Hard to grab context (scattered Confluence, human resources)
  - Hidden dependencies across the product
  - Partially manual work
  - Time consuming rediscovery
- Visual idea: Five sparse pain icons/labels in one calm composition (not a dense dashboard)

## Slide 4: Before vs After
- Role: comparison
- Key points:
  - Before: chat-driven rediscovery, re-explain context every time
  - After: Inbox → skills/micro-workflows → knowledge graph → execute
  - Side-by-side timeline / comparison of the two operating modes
- Visual idea: Two panels — left vibe loop, right durable pipeline

## Slide 5: Knowledge alone is not enough
- Role: concept explanation
- Key points:
  - Knowledge Base (content only) ≈ a book
  - Skills + Micro-workflows (actionable agents) + Knowledge ≈ matured architect
  - The architect executes tasks, not just retrieves text
- Visual idea: Book metaphor vs architect/agent metaphor, clear contrast

## Slide 6: What we built — the `base/` framework
- Role: architecture
- Key points:
  - Inbox → Knowledge Orchestrator → Skill Pipeline → Structured Vault → Knowledge Graph
  - Pipeline: Intake → Classify → Retrieve → Plan → Generate → Link → Tag → Validate → Summarize
  - 12 skills as governable micro-workflows (not one free-form agent)
- Visual idea: Clean hand-drawn architecture flow (redraw, not screenshot)

## Slide 7: A knowledge graph that evolves
- Role: process
- Key points:
  - Typed links: requires / depends_on / uses / validates
  - Build up and evolve over time
  - Used inside long-horizon activities (not one-shot Q&A)
- Visual idea: Growing node graph with typed arrows; “build → evolve → use”

## Slide 8: Two kinds of work
- Role: split layout / concept
- Key points:
  - Task type A: Understand the underlying structure of the existing product
  - Task type B: Knowing that structure, execute tasks based on the given architecture
  - Same vault supports both understanding and action
- Visual idea: Two columns / two task cards with distinct icons

## Slide 9: Breakthrough insight
- Role: insight / quote
- Key points:
  - We learned long-running tasks are possible
  - Not continuous vibe-code guidance for every step
  - Durable context lets agents work across longer horizons
- Visual idea: Large insight statement with small before/after cue

## Slide 10: Demo agenda
- Role: demo board
- Key points:
  - Live demo 1: Domain-relevant question against the vault
  - Live demo 2: Ask for an improvement to the vault
  - Show understanding + structured update intent
- Visual idea: Two big numbered demo cards; leave space for presenter to talk over

## Slide 11: What judges should take away
- Role: summary / close
- Key points:
  - Durable context beats re-prompting every time
  - Skills + knowledge graph = executable architecture literacy
  - Framework is domain-agnostic; Service Bus vault is the proof instance
  - Closing ask: evaluate the pattern, not only the domain content
- Visual idea: Three takeaway labels + small vault mark; calm closing
